FOODBRIDGE FRONTEND API CONNECTION (NO UI REDESIGN REQUIRED)

Because the frontend is hosted on GitHub Pages and the Flask API is hosted elsewhere,
your existing api() helper must use the deployed backend URL instead of relative paths.

In your existing foodbridge.js, replace only the api() helper with the snippet below.
Put your actual Render service URL into API_BASE_URL. Do not add a trailing slash.

const API_BASE_URL = "https://YOUR-FOODBRIDGE-BACKEND.onrender.com";

async function api(path, options = {}) {
  const response = await fetch(`${API_BASE_URL}${path}`, {
    ...options,
    credentials: "include",
    headers: {
      "Content-Type": "application/json",
      ...(options.headers || {})
    }
  });
  const result = await response.json().catch(() => ({}));
  if (!response.ok) {
    throw new Error(result.error || `Request failed (HTTP ${response.status}).`);
  }
  return result;
}

The backend requires FRONTEND_ORIGINS to contain the EXACT origin of your GitHub Pages site,
for example https://YOUR-USERNAME.github.io (no path or trailing slash).
Do not use wildcard CORS origins with credentialed sessions.

Note: GitHub Pages and Render are separate sites. Cross-site session cookies require HTTPS and
may be restricted by browser third-party-cookie settings. If login sessions do not persist,
the more reliable setup is to serve the frontend and Flask API from the same origin, while still
keeping all source code in GitHub.
